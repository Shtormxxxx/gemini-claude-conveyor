# Конвейер задач: Gemini Pro + Claude Pro

Один запрос в **Google Antigravity** запускает весь цикл разработки:
**план** (Claude) → **код** (вкладки Gemini в Chrome) → **сборка и проверки** → **ревью** (Claude) → **выкладка**.
Ты пишешь задачу одной строкой. Конвейер останавливается и спрашивает тебя, только когда без твоего решения нельзя.

> **English.** A task conveyor for Google Antigravity: one `/conveyor <task>` runs plan (Claude Code,
> headless) → code (Gemini tabs in Chrome, driven by Antigravity's browser agent) → checks →
> pre-review (a Gemini tab that wrote none of the run) → review (Claude) → commit, push and deploy.
> A small Node.js program does every exact step and enforces the guards: a clean start, protected
> paths, a secret scan, review-before-ship of the exact diff, a quota guard for the Gemini tabs, and
> a guard on the Claude subscription's real five-hour and weekly limits that picks the model for each
> step. Claude's steps run lean (five tools, no MCP servers or skills) and a second review reads only
> what changed. Installs into any git project with `init`; also installs
> [ECC](https://github.com/affaan-m/ECC) for Antigravity. No dependencies; Node 20+.

## Как это устроено

```
        ты: /conveyor 8 Добавь на главную блок с тарифами
                              │                 (8 — сколько рабочих аккаунтов: 4 или 8)
1. ПЛАН          Claude (Claude Code в фоне) читает нужные файлы и делит работу
                 максимум на 8 заданий — по одному на вкладку
                              │
2. КОД           Antigravity через @browser рассылает задания по вкладкам Gemini в Chrome,
                 они пишут код одновременно; программа раскладывает файлы по проекту
                              │
3. СБОРКА        Antigravity связывает импорты; программа гоняет проверки (lint, test, build)
                              │
3б. ПРЕДРЕВЬЮ    свободная вкладка Gemini (не писавшая код в этом прогоне) читает дифф
                 и присылает исправленные файлы за явные ошибки — лимит Claude не тратится
                              │
4. РЕВЬЮ         Claude читает только дифф, точечно чинит, выносит вердикт
                 APPROVE / REWORK / ESCALATE; повторное ревью — только то, что изменилось
                              │
5. ВЫКЛАДКА      проверки ещё раз → коммит → push → твои команды деплоя → проверка в браузере
```

| Роль | Кто | Что делает |
|---|---|---|
| Архитектор | Claude Pro (Claude Code, в фоне) | план и задания для вкладок; длинный код не пишет, экономит лимит |
| Кодеры | рабочие аккаунты Gemini во вкладках Chrome — 4 или 8 за прогон, по почте | пишут файлы целиком по готовым заданиям, одновременно |
| Предревьюер | рабочий аккаунт, который в этом прогоне код не писал | первым читает дифф, исправляет явные ошибки |
| Дирижёр | Antigravity (Gemini Flash) + @browser | носит задания и ответы, запускает команды, чинит мелочи |
| Ревьюер | Claude Pro (Claude Code, в фоне) | проверяет дифф, правит, решает, можно ли выкладывать |
| Программа | `node conveyor/bin/conveyor.mjs` | всё точное: копирует, считает, проверяет, выбирает модель Claude по лимитам, не пускает лишнее |

## Что нужно

- **Git** и **Node.js 20+** — https://nodejs.org
- **Claude Pro** и **Claude Code**:
  ```
  npm install -g @anthropic-ai/claude-code
  ```
  Если после установки `claude --version` пишет «не является командой», поставь официальным установщиком
  (PowerShell): `irm https://claude.ai/install.ps1 | iex`
- **Google Antigravity** с подпиской Google AI Pro. Браузерный агент (`@browser`) должен быть подключён к Chrome.
- Аккаунты Google с Gemini во вкладках Chrome. Схема по умолчанию — **1 главный + до 8 рабочих**: главный в
  Antigravity, рабочие в Chrome. Можно и меньше: составы настраиваются, вплоть до одной вкладки.

## Установка в свой проект

Проект должен быть git-репозиторием (`git init`, если ещё нет).

**1. Скачай конвейер** (один раз, в любую папку):
```
git clone https://github.com/Shtormxxxx/gemini-claude-conveyor
```

**2. Поставь его в проект** (Windows, cmd; путь в кавычках, если в нём пробелы):
```
node "C:\путь\к\gemini-claude-conveyor\bin\conveyor.mjs" init "C:\путь\к\твоему\проекту"
```
Что появится в проекте:

| Путь | Что это |
|---|---|
| `conveyor/` | программа, шаблоны, `conveyor.config.json`, инструкция |
| `.agents/workflows/conveyor.md` | команда `/conveyor` для Antigravity |
| `AGENTS.md`, `CLAUDE.md` | правила для агентов (отдельный размеченный раздел, остальное не трогается) |
| `.gitignore` | файлы прогонов и локальные файлы ECC не попадают в Git |

Заодно поставится **ECC** для Antigravity (см. ниже). Если он не нужен, добавь `--no-ecc`.

**3. Укажи рабочие аккаунты по почте**, по порядку (в папке проекта):
```
node conveyor/bin/conveyor.mjs accounts work1@gmail.com work2@gmail.com work3@gmail.com work4@gmail.com
```
Первая почта станет ARGON_1, вторая ARGON_2 и так далее, до 8. Почты сохраняются в `conveyor/accounts.local.json`.
Этот файл Git не видит, поэтому в опубликованном проекте почт нет. Почему по почте, а не по номеру — ниже, в «Аккаунты и составы».

Можно не вводить почты самому: попроси Antigravity открыть Gemini через @browser, выписать почты из меню
аккаунта (кроме главного) и выполнить эту команду.

**Потом открой `conveyor/conveyor.config.json`** и проверь:
- `project` — одна строка о проекте: стек, язык, что важно. Её видят кодеры, у которых нет доступа к файлам;
- `checks` — команды проверки (для Node-проекта подставляются из `package.json` сами);
- `deploy` — команды выкладки (можно оставить пустым, тогда будут только коммит и push);
- `tabs` — рабочие аккаунты, их записала команда `accounts`.

**4. Сохрани в Git:**
```
git add -A
git commit -m "Конвейер"
```

**5. Один раз запусти Claude Code в папке проекта:**
```
claude
```
1. Войди аккаунтом Claude Pro.
2. На «Do you trust the files in this folder?» ответь **Yes**.
3. На вопросы про MCP-серверы ответь **Continue without**.
4. Выйди: `/exit`.

**6. Проверь готовность:**
```
node conveyor/bin/conveyor.mjs doctor
```
Должно появиться `CONVEYOR: READY`. Если нет — в каждой строке с `✗` написано, что сделать.

**7. В Antigravity:**
1. **File → Open Folder** → папка проекта, режим **Local**.
2. Нажми **New Conversation**.
3. Набери:
```
/conveyor 4 Добавь кнопку «Наверх» в подвал сайта
```
Число — сколько рабочих аккаунтов задействовать (4 или 8). Без числа Antigravity один раз спросит.

## Аккаунты и составы

Один **главный** аккаунт работает в Antigravity (дирижёр). **Рабочие** — вкладки Gemini в Chrome, до 8 штук.
На всех аккаунтах нужна подписка с доступом к сильной модели.

**Аккаунты задаются по почте, а не по номеру.** Номер в адресе `gemini.google.com/u/N/app` — это не
аккаунт, а порядок, в котором аккаунты вошли в Chrome. Он дырявый и меняется: после выхода и нового
входа аккаунт может оказаться на `/u/2/` вместо `/u/1/` или на `/u/5/`. Поэтому:
- вкладки записываются по почте: `node conveyor/bin/conveyor.mjs accounts a@gmail.com b@gmail.com …`;
- **почты не попадают в Git**: они лежат в `conveyor/accounts.local.json`, который игнорируется. В конфиге,
  который уходит в Git, только номера вкладок. На другом компьютере (или у друга) команду `accounts`
  выполняют один раз заново, своими почтами;
- если почта рабочего аккаунта появится в изменениях (в коде или тексте), выкладка остановится и будет ждать
  твоего слова, как и с ключами;
- вкладка открывается адресом `gemini.google.com/app?authuser=почта`, и Google сам находит, на каком
  номере сейчас этот аккаунт;
- перед отправкой Antigravity открывает меню аккаунта и сверяет почту. Если открыт другой аккаунт, он
  переключается на нужный. Если нужного нет в Chrome, вкладка блокируется на окно квоты, а её задание
  делает сам дирижёр;
- `doctor` предупреждает о вкладках, которые всё ещё заданы номером.

Перед прогоном выбираешь **состав** — сколько рабочих аккаунтов задействовать:

| Состав | Всего аккаунтов | Вкладки | Когда |
|---|---|---|---|
| **4** | 5 (1 + 4) | ARGON_1 … ARGON_4 | обычные задачи; половина аккаунтов в запасе |
| **8** | 9 (1 + 8) | ARGON_1 … ARGON_8 | большие задачи, все аккаунты |

- Claude делит работу максимум на столько заданий, сколько вкладок в составе, но **не больше, чем она
  делится по смыслу**: маленькой задаче хватит одной вкладки и при составе 8.
- Если вкладка в составе на пределе квоты, её задание берёт свободная вкладка того же состава.
  Вкладки вне состава не трогаются: это твой запас.
- Свои размеры — в `crews` (например `[5, 10]`, если вкладок 10), сами вкладки — в `tabs`. Чтобы не
  спрашивать каждый раз, поставь `"crew": 8`.
- Совет: при составе 8 @browser рассылает задания по вкладкам по очереди, это занимает пару минут.
  Выигрыш — когда задача правда делится на много файлов.

## Защита (гарды)

Агент может ошибиться или поддаться странному тексту из ответа модели. Поэтому всё важное проверяет программа:

| Гард | Что делает |
|---|---|
| **Чистый старт** | прогон начинается только с сохранённой папки, поэтому дифф — ровно работа прогона |
| **План без правок** | если Claude при планировании изменил файлы проекта, прогон останавливается |
| **Никаких секретов в чатах** | `.env`, ключи, `*.pem`, `credentials*.json` и подобное никогда не вставляются во вкладки |
| **Запретные пути для ответов** | ответы из вкладок не пишут в секреты, `.git`, `node_modules`, сборку, lock-файлы, сам конвейер и правила агентов (даже в файлы прогона: вердикт подделать нельзя) |
| **Оборванный ответ** | файл, на котором ответ оборвался, не записывается наполовину. Конвейер просит прислать его заново |
| **Ревью точного диффа** | выкладка идёт только после `APPROVE`, и только того диффа, который проверил Claude; любая правка после ревью её блокирует |
| **Ревью свежего диффа** | Claude проверяет только ту папку, которую описал последний `diff`: если после него что-то поменялось, ревью не начнётся |
| **Правки ревьюера проверяются** | если Claude что-то поправил, программа снова гоняет проверки; сломалось — вердикт становится REWORK |
| **Ответ не применяется дважды** | ответ вкладки, уже записанный в проект, повторный `apply` не накатывает поверх правок дирижёра и ревьюеров |
| **Предревью без секретов и без чужих файлов** | дифф с чем-то похожим на ключ или почту рабочего аккаунта в чат не уходит; предревьюер правит только файлы этого прогона |
| **Только с твоего слова** | зависимости, CI, `.gitignore`, файлы секретов, сам конвейер, правила агентов и твои пути из `ownerOnly` выкладываются только командой `ship --owner-ok`, которую набираешь ты |
| **Поиск ключей в диффе** | строки, похожие на ключи Google/OpenAI/Anthropic/GitHub/AWS/Stripe/Slack, приватные ключи или почты рабочих аккаунтов, держат выкладку до твоего слова |
| **Слишком большой прогон** | больше `limits.maxChangedFiles` файлов (по умолчанию 60) — только с твоего слова |
| **Отмена без потерь** | `abort` убирает изменения прогона в `git stash`, их можно вернуть |

## Квоты (Quota Guard)

Мощная модель во вкладке тратит пятичасовой лимит намного быстрее быстрой. Узнать остаток у Google
программа не может, поэтому считает сама: каждое задание, отправленное во вкладку, — один «тяжёлый
запрос» в скользящем окне.

- Каждой вкладке положено `quota.budget` запросов за `quota.windowHours` часов. По умолчанию 12 за 5 часов,
  это примерно 70–75% лимита, остальное остаётся в запасе.
- Вкладка на пределе пропускает ход до освобождения окна. Её задание получает вкладка того же
  состава, у которой больше всего места и меньше всего заданий в этом прогоне.
- Если места нет ни у одной вкладки состава, задание берёт **запасной** аккаунт вне состава: при составе 4 —
  вкладки 5–8. Так состав работает в полную силу, пока у кого-то есть лимит. Выключить: `"spares": false`.
- Если места нет вообще, обычные задания делает быстрая модель Antigravity, а помеченные
  в плане как `WEIGHT: heavy` — модель Claude в Antigravity: у неё отдельный лимит.
- Сам дирижёр: если в **View Usage** Antigravity осталось 30% или меньше лимита Gemini, он на весь прогон
  переключается на Claude.
- Ручные запросы во вкладках конвейер не видит. Если Gemini пишет про лимит, отметь вкладку:
  `node conveyor/bin/conveyor.mjs status --block ARGON_1`. Снять — `--unblock`, обнулить — `--reset`.

## Экономия лимита Claude (1.5)

Узкое место конвейера — одна подписка Claude Pro: на ней план и ревью каждого прогона. Gemini-аккаунтов
может быть много, Claude один. Поэтому в 1.5 Claude тратит меньше на каждый шаг, делает меньше шагов
и сам переходит на модель подешевле, когда лимит кончается. Качество держат три вещи: план всегда пишет
сильная модель, рискованное ревью — тоже, а проверки (lint, test, build) прогоняются на каждой правке.

**1. Лёгкие шаги.** Каждый ход Claude заново отправляет всё, что загружено: системную подсказку, описания
инструментов, навыки, MCP-серверы. Конвейеру нужны пять инструментов (Read, Glob, Grep, Edit, Write), так что
остальное не загружается. Замер на реальном проекте: **42 437 токенов обвязки на ход было, 11 377 стало** (−73%).
В плане 5–15 ходов, в ревью столько же, и экономия повторяется на каждом.

**2. Меньше ходов.** Архитектор получает карту файлов проекта и сразу открывает нужные, вместо того
чтобы искать. Ревьюер получает план и дифф прямо в задании, а не открывает их сам. Тесты ревьюер больше
не запускает: после его правок проверки гоняет программа. Если правки что-то сломали, это REWORK.

**3. Повторное ревью — только изменения.** После REWORK Claude читает свой прошлый вердикт и дифф с момента
того ревью, а не весь прогон заново.

**4. Предварительное ревью.** Перед Claude дифф читает рабочий аккаунт Gemini, который в этом прогоне
код не писал, и исправляет явные ошибки. Claude видит весь дифф вместе с этими правками. Кругов REWORK
становится меньше, а Gemini-аккаунтов у тебя много.

**5. Модель по настоящим лимитам.** Перед каждым шагом и после него программа делает крошечный вызов (Haiku,
без инструментов, вне проекта) и узнаёт у Claude Code настоящий расход подписки. В расчёт идёт и твоя ручная
работа с Claude. Дальше правила:

| Когда | Модель |
|---|---|
| обычно | основная — `claude.model` (`opus`, усилие `high`) |
| ревью, которое план назвал обычным (`REVIEW: standard`) | экономная — `claude.economy` (`sonnet`, усилие `xhigh`) |
| пятичасовой лимит ≥ `claude.switchAt` (50%) | экономная, на всех шагах |
| неделя тратится быстрее, чем идёт: израсходовано больше, чем прошло времени, плюс `claude.weekAhead` (15) пунктов | экономная, пока время не догонит |
| Claude отказал только основной модели (например, недельный лимит на Opus) | экономная, до сброса |
| пятичасовой или недельный лимит ≥ `claude.stopAt` (95%) | шаг не начинается, чтобы не оборваться на середине; конвейер говорит, когда лимит обновится |

- Ревью с файлами из `ownerOnly`, зависимостями или чем-то похожим на ключ всегда **глубокое**, даже если план
  сказал `standard`; без строки `REVIEW` тоже. Глубокое ревью, как и план, идёт на основной модели, пока
  лимиты из таблицы это позволяют.
- После каждого шага видно его цену: «Claude's limits now: five-hour 31%, this step 6%». `status` показывает
  лимиты, модель для следующих шагов и цену последних шагов.
- Если основная модель перегружена, Claude Code сам переходит на экономную (`--fallback-model`).
- Только Sonnet: `"claude": { "model": "sonnet" }`. Без недельного темпа: `"weekAhead": null`.
  Разово на один прогон: `set CONVEYOR_MODEL=sonnet`.

## ECC для Antigravity

[ECC](https://github.com/affaan-m/ECC) от affaan-m (MIT) добавляет в Antigravity правила, навыки,
агентов и воркфлоу.

- **Ставится сам:** при `init` и перед каждым прогоном, если его нет. Ставится в `.agents/` проекта командой
  `npx ecc-universal@<версия> install --profile minimal --target antigravity`.
- **Версия закреплена** в `conveyor.config.json` (`ecc.version`). Чужие обновления сами не прилетают.
  Обновить — поменяй версию и запусти `node conveyor/bin/conveyor.mjs setup`.
- **Профиль `minimal`** — без хуков, только файлы.
- **Файлы ECC не попадают в Git:** ECC записывает абсолютные пути машины, поэтому у каждого он ставится
  свой. В Git идёт только `.agents/workflows/conveyor.md`.
- **Выключить:** `"ecc": { "enabled": false }`.

## Настройки: `conveyor/conveyor.config.json`

| Ключ | По умолчанию | Что значит |
|---|---|---|
| `project` | из `package.json` | одна строка о проекте для кодеров |
| `reportLanguage` | `Russian` | язык отчётов Antigravity тебе |
| `checks` | из `package.json` | команды проверки, по порядку |
| `deploy` | `[]` | команды выкладки: строка — всегда; `{ "run": "...", "when": "^api/" }` — только если менялись такие пути |
| `push` | `true` | делать `git push` после коммита |
| `claude.model`, `claude.effort` | `opus`, `high` | основная модель для плана и глубокого ревью. Разово на все шаги: `set CONVEYOR_MODEL=sonnet` |
| `claude.economy` | `sonnet`, `xhigh` | экономная модель: обычные ревью, а также шаги при расходе лимита (см. «Экономия лимита Claude») |
| `claude.switchAt`, `claude.stopAt` | `50`, `95` | с какого % пятичасового лимита работает экономная модель; на каком % лимита шаги не начинаются |
| `claude.weekAhead` | `15` | на сколько пунктов неделя может опережать время до перехода на экономную модель; `null` — не следить |
| `claude.reviewByRisk` | `true` | обычные ревью (`REVIEW: standard`) — на экономной модели; `false` — все ревью на основной |
| `spares` | `true` | аккаунты вне состава подменяют вкладку состава без лимита |
| `prereview` | вкл., от `40` строк | предварительное ревью свободной вкладкой; `maxChars` — сколько диффа и файлов ей отправить |
| `tabs` | 8 вкладок по номеру `/u/1/` … `/u/8/` — замени командой `accounts` | `{ "id": "ARGON_1", "model": "Gemini 4 Argon" }`; почту берёт из `accounts.local.json` по порядку; `url` — свой адрес, если нужен |
| `crews` | `[4, 8]` | из каких составов выбирать перед прогоном (состав N — первые N вкладок) |
| `crew` | `null` | `null` — спрашивать каждый раз; число — всегда этот состав |
| `quota` | `12` за `5` ч | бюджет каждой вкладки |
| `limits` | `60` файлов, `150000` символов диффа | порог «слишком большого» прогона и сколько диффа видит ревьюер |
| `secrets`, `neverWrite`, `ownerOnly` | `[]` | твои добавки к встроенной защите. Убрать встроенную нельзя |
| `ecc` | `2.2.3`, `minimal` | ECC для Antigravity |

## Команды

Все команды — из корня проекта: `node conveyor/bin/conveyor.mjs <команда>`.

| Команда | Что делает |
|---|---|
| `doctor` | что готово, а что нет |
| `accounts <почта> <почта> …` | записать рабочие аккаунты по почте, по порядку, в `accounts.local.json` (не в Git); без почт — показать текущие |
| `status` | лимиты Claude и модель для следующих шагов, квоты вкладок, последние прогоны; `--block` / `--unblock` / `--reset <TAB>` |
| `setup` | поставить ECC вручную |
| `abort` | бросить прогон: изменения в `git stash` |
| `plan --crew N`, `apply`, `diff`, `prereview`, `review`, `ship` | шаги прогона, их запускает Antigravity |
| `ship --owner-ok` | выложить то, что ждёт твоего слова. Только ты |

Каждая команда заканчивается строкой `CONVEYOR: …`: что случилось и что дальше.

## Обновление

1. Закончи текущий прогон (`ship`) или отложи его: `node conveyor/bin/conveyor.mjs abort`. Посреди прогона
   `init` не обновляет.
2. Скачай свежую версию: `git pull` в папке конвейера.
3. Снова выполни `init` для проекта. Программа и воркфлоу обновятся, твой `conveyor.config.json` останется как был:
   новые настройки допишутся с умолчаниями, твои значения не тронутся. Если в нём ещё стоят две вкладки версии 1.0,
   они станут восемью рабочими с составами 4 и 8.
4. Закоммить (`git add -A`, `git commit -m "Conveyor 1.5.0"`) и проверь: `node conveyor/bin/conveyor.mjs doctor`.
5. В Antigravity начни **новый разговор**, чтобы он прочитал новый воркфлоу.

### Что нового

- **1.5** — лимит Claude Pro тратится в разы медленнее, качество прежнее:
  - каждый шаг Claude грузит только 5 инструментов, без MCP и навыков (обвязка хода: 42k → 11k токенов);
  - архитектор получает карту файлов, ревьюер — план и дифф прямо в задании;
  - тесты после правок ревьюера гоняет программа;
  - повторное ревью читает только изменения;
  - предварительное ревью делает свободный аккаунт Gemini;
  - модель для каждого шага выбирается по настоящему расходу подписки, пяти часов и недели:
    Opus для плана и рискованного ревью, Sonnet для обычного ревью и при расходе лимита, стоп у 95%;
  - запасные аккаунты вне состава подменяют вкладки без лимита;
  - `status` показывает лимиты Claude и цену каждого шага;
  - ответ из вкладки больше не применяется второй раз поверх правок;
  - Claude проверяет только тот дифф, что сейчас в папке.
- **1.4** — почты рабочих аккаунтов хранятся в `conveyor/accounts.local.json` и не попадают в Git; `init`

- **1.2** — рабочие аккаунты задаются по почте (`accounts`), а не по номеру `/u/N/`, который меняется

## Частые проблемы

| Что видишь | Что делать |
|---|---|
| `claude` «не является командой» | новый npm не запустил установочный скрипт. Поставь через PowerShell: `irm https://claude.ai/install.ps1 \| iex`, потом открой новое окно терминала |
| `STOP — the folder has changes from before this run` | закоммить свои изменения (`git add -A`, `git commit -m "..."`) и запусти заново |
| `STOP — Claude: the five-hour limit is at 96%, until 14:20` | лимит Claude Pro почти кончился. Шаг не начат, чтобы не оборваться на середине. Повтори после указанного времени |
| `STOP — Claude refused opus …; the next steps use sonnet` | исчерпан отдельный лимит на Opus. Просто повтори шаг: он пойдёт на Sonnet |
| `STOP — the folder changed after diff ran` | после `diff` что-то поменялось. Запусти `diff`, потом `review` |
| `Claude stopped (exit code …)` | прочитай текст рядом. Если не вошёл в Claude Code — запусти `claude` и войди |
| Antigravity не видит `/conveyor` | новый разговор (**New Conversation**). Проверь, что есть файл `.agents/workflows/conveyor.md` |
| `git pull` ругается на локальные изменения | `git status`, сохрани или верни свои изменения, повтори |
| Файл создался как `имя.js.txt` | в Проводнике включи **Вид → Расширения имён файлов** и переименуй |
| `LF will be replaced by CRLF` | безвредное предупреждение Git в Windows |

## Честно об ограничениях

- **Браузер — самое хрупкое звено.** Если интерфейс Gemini поменяется, @browser может не найти кнопку.
  Тогда Antigravity сам пишет эту часть по тому же заданию, а прогон продолжается.
- **Квоты — оценка.** Настоящий остаток знает только Google. Подгони `quota.budget` под свои наблюдения.
- **Условия сервисов.** Автоматизация веб-интерфейса Gemini и работа с несколькими аккаунтами ради лимитов
  могут противоречить условиям Google. Решай сам. Конвейер работает и с одной вкладкой, и вообще без вкладок
  (тогда задания делает Antigravity).
- **Лимиты Claude Pro** тратятся на план и ревью. Сколько ушло, Claude Code сообщает сам, и конвейер выбирает
  модель по этим цифрам. Сами пороги лимитов задаёт Anthropic, и они могут меняться. Цена каждого шага
  видна в его выводе и в `status`.
- Тесты гоняются на Linux и Windows (`npm test`): полный прогон с заглушкой вместо Claude.
