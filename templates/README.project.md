# Конвейер в этом проекте

Один запрос в Antigravity → план (Claude) → код (вкладки Gemini) → проверки → предварительное ревью
(свободная вкладка Gemini) → ревью (Claude) → выкладка.

## Запуск

В Antigravity, в папке проекта:
```
/conveyor 8 Добавь на главную блок с тремя тарифами
```
Число в начале — сколько рабочих аккаунтов задействовать: **4 или 8**. Без числа Antigravity один раз
спросит. Дальше всё идёт само и останавливается только там, где нужно твоё решение.

## Что лежит в этой папке

| Файл | Что это |
|---|---|
| `conveyor.config.json` | настройки: описание проекта, проверки, команды выкладки, вкладки, квоты, защита |
| `bin/`, `lib/`, `templates/` | сама программа. Не правь, обновляется командой `init` |
| `run/` | файлы текущего прогона: задача, план, промпты, ответы, ревью, счётчик квот. В Git не попадает |

## Когда конвейер остановится и спросит тебя

1. **В папке есть несохранённые изменения** до начала прогона: закоммить их и запусти заново.
2. **ESCALATE** — нужно твоё решение: деньги, правила доступа, удаление данных, новые зависимости,
   изменения самого конвейера.
3. **Изменены защищённые файлы**, в диффе что-то похожее на ключ, или прогон слишком большой.
   Посмотри список. Если согласен — выкладку запускаешь ты сам:
   ```
   node conveyor/bin/conveyor.mjs ship --owner-ok
   ```

## Команды

| Команда | Что делает |
|---|---|
| `node conveyor/bin/conveyor.mjs doctor` | проверяет, всё ли готово, и говорит, что починить |
| `node conveyor/bin/conveyor.mjs status` | лимиты Claude (5 часов и неделя), на какой модели пойдут следующие шаги, квоты вкладок, последние прогоны |
| `node conveyor/bin/conveyor.mjs status --block ARGON_1` | вкладка на пределе: не трогать её одно окно |
| `node conveyor/bin/conveyor.mjs abort` | бросить прогон: изменения уходят в `git stash`, их можно вернуть |
| `node conveyor/bin/conveyor.mjs setup` | поставить ECC для Antigravity вручную (обычно ставится сам) |

Остальные команды (`plan`, `apply`, `diff`, `prereview`, `review`, `ship`) запускает Antigravity по воркфлоу.

## Лимиты Claude

Перед каждым планом и ревью конвейер узнаёт у Claude Code настоящий расход подписки: сколько процентов
пятичасового и недельного лимита уже ушло, включая то, что ты тратил сам. По этим цифрам он выбирает модель:

| Когда | Модель |
|---|---|
| обычно | основная: `opus`, усилие `high` |
| ревью, которое план назвал обычным (`REVIEW: standard`: вёрстка, тексты, простые компоненты) | экономная: `sonnet`, усилие `xhigh` |
| пятичасовой лимит израсходован на 50% и больше | экономная, на всех шагах |
| неделя тратится быстрее, чем идёт (больше чем на 15 пунктов впереди) | экономная, пока время не догонит |
| любой лимит на 95% | шаг не начинается: конвейер скажет, когда лимит обновится |

Ревью безопасности, доступа к данным, денег и файлов, которые ты защищаешь, всегда глубокое: оно, как и план,
идёт на основной модели, пока лимиты это позволяют.
После каждого шага видно, сколько он стоил: «this step 4%». Пороги меняются в `conveyor.config.json`,
в разделе `claude`.

## Аккаунты

Один главный аккаунт — в Antigravity (дирижёр). Рабочие — вкладки Gemini в Chrome. Укажи их **по почте**,
по порядку (первая почта — ARGON_1 и т. д.):
```
node conveyor/bin/conveyor.mjs accounts work1@gmail.com work2@gmail.com work3@gmail.com …
```
Почты сохраняются в `conveyor/accounts.local.json`: этот файл Git игнорирует, так что в опубликованном
проекте почт не будет. На другом компьютере команду выполняют один раз заново.

Номера `/u/N/` в адресе Gemini — не аккаунты, а порядок входа в Chrome: после выхода и нового входа
аккаунт может переехать с `/u/1/` на `/u/5/`. По почте вкладка всегда открывает нужный аккаунт
(`?authuser=почта`), а Antigravity перед отправкой сверяет почту в меню аккаунта.

Состав выбирается на каждый прогон:

| Состав | Аккаунтов всего | Вкладки (первые N почт) |
|---|---|---|
| 4 | 5 (1 + 4) | ARGON_1 … ARGON_4 |
| 8 | 9 (1 + 8) | ARGON_1 … ARGON_8 |

Claude делит работу максимум на столько заданий, сколько вкладок в составе, но не больше, чем она
делится по смыслу. Маленькой задаче хватит одной вкладки при любом составе. Размеры составов и
вкладки — в `conveyor.config.json` (`crews`, `tabs`). Чтобы не спрашивать каждый раз, поставь
`"crew": 8`.

## Квоты

Конвейер сам считает, сколько тяжёлых запросов отправил в каждую вкладку за окно (по умолчанию
12 за 5 часов, это примерно 70–75% лимита). Вкладка на пределе пропускает ход, и её задание
получает свободная вкладка того же состава. Если места нет нигде в составе, задание берёт **запасной**
аккаунт вне состава: при составе 4 это вкладки 5–8. Только когда места нет вообще, задание делает быстрая
модель Antigravity, а тяжёлое — модель Claude в Antigravity. Запросы, которые ты делал во вкладках
вручную, конвейер не видит: отметь их через `status --block`.

## Предварительное ревью

Перед Claude дифф читает рабочий аккаунт, который в этом прогоне код не писал. Он присылает исправленные
файлы целиком за явные ошибки, а Claude потом проверяет весь дифф вместе с этими правками. Лимит Claude
на это не тратится, а повторных кругов ревью становится меньше. Срабатывает, когда изменено от 40 строк.
Дифф, где есть что-то похожее на ключ или почту рабочего аккаунта, в чат не отправляется никогда.
